# Ритм — личный трекер привычек

Ритм — самостоятельное веб-приложение для ведения ежедневных привычек, просмотра истории и статистики. Сервер и база данных размещаются на вашем компьютере; телефон подключается к ним через частную домашнюю сеть.

> **Статус:** ранняя версия `0.1.0`. Полная приёмка на реальных устройствах и независимый аудит безопасности не проводились. Это описание объясняет текущую реализацию, но не является подтверждением готовности к эксплуатации.

## Возможности

- Отметки привычек в недельной сетке, в том числе за прошедшие дни.
- Создание, изменение, сортировка, архивирование и восстановление привычек.
- Эмодзи, собственный цвет, теги и необязательные числовые цели с фактическим значением.
- Статистика по привычкам и периодам: проценты, серии, сравнение недель, диаграммы и рейтинги.
- Локальная SQLite-база на компьютере и отдельная IndexedDB-копия в каждом браузере.
- Очередь локальных изменений и синхронизация браузеров с сервером по домашней сети.
- Тёмный интерфейс с отдельной компоновкой для узких и широких экранов.

Приложение открывается как обычная веб-страница в Safari, Edge, Chrome и других современных браузерах. Установка как отдельное приложение/PWA и фоновая работа после закрытия страницы сейчас не поддерживаются. Чтобы накопленные на устройстве отметки отправились на сервер, страница должна оставаться открытой; синхронизация возобновится при доступе к серверу.

## Важное предупреждение о сети

Текущий локальный сервер использует **обычный HTTP без шифрования**. Пароли и аккаунты приложение не использует, но данные привычек и синхронизационный трафик могут быть видны другим участникам сети.

- Запускайте сервер только в доверенной частной сети, например дома.
- Не подключайте его к публичной Wi-Fi-сети и не перенаправляйте порт с роутера в интернет.
- Для телефона задавайте `HOST` равным адресу именно домашнего сетевого интерфейса, а не `0.0.0.0`.
- Сертификаты, корневые центры доверия и профили на устройства устанавливать не требуется; приложение их не создаёт.

## Требования

- Node.js **22 или новее** (ограничение текущей версии `better-sqlite3`).
- npm (обычно устанавливается вместе с Node.js).
- Windows-компьютер для сервера.
- Если нужен доступ с телефона: компьютер и телефон в одной доверенной домашней сети.

## Установка и запуск на компьютере

В PowerShell перейдите в каталог проекта и установите зависимости:

```powershell
Set-Location 'путь\к\проекту'
npm install
```

По умолчанию сервер привязывается только к `127.0.0.1:8080`. Это безопасное локальное значение: другие устройства не смогут подключиться. Для проверки на самом компьютере запустите:

```powershell
npm start
```

Затем откройте <http://localhost:8080>. Чтобы остановить сервер, нажмите **Ctrl+C** в окне, где он запущен.

## Подключение телефона в домашней сети

1. Узнайте IPv4-адрес активного домашнего Wi-Fi или Ethernet-интерфейса компьютера:

   ```powershell
   Get-NetIPConfiguration |
     Where-Object { $_.IPv4DefaultGateway } |
     Select-Object InterfaceAlias, IPv4Address, IPv4DefaultGateway
   ```

2. Выберите адрес обычного домашнего интерфейса. Не используйте `127.0.0.1`, VPN-адрес или виртуальный адаптер. Закрепление постоянного адреса в настройках роутера полезно, но необязательно.

3. Привяжите сервер к этому **конкретному** адресу и запустите его:

   ```powershell
   $env:HOST = '192.168.1.42' # замените на адрес вашего компьютера
   $env:PORT = '8080'
   npm start
   ```

   Переменные задаются в текущем окне PowerShell. Если открыть новое окно, укажите их снова.

4. На компьютере и телефоне откройте адрес одного сервера, например `http://192.168.1.42:8080`. На экране подключения введите этот же адрес и нажмите **«Подключиться»**.

5. Если Windows спросит разрешение для Node.js в брандмауэре, разрешайте соединения только в частной домашней сети. Если подключение с телефона блокируется, проверьте категорию сети Windows и создайте узкое входящее правило для TCP-порта `8080` и только для домашней подсети. Не отключайте брандмауэр целиком.

Если порт `8080` занят, выберите другой и используйте его в адресах на всех устройствах:

```powershell
$env:HOST = '192.168.1.42'
$env:PORT = '8081'
npm start
```

Адрес на телефоне в таком случае будет `http://192.168.1.42:8081`.

## Хранение данных и резервные копии

- Основная база текущего приложения: `data/ritm.db`.
- Старый файл `data/habit-os.db` оставлен отдельно. Новый сервер его не открывает и не меняет.
- База содержит личную историю привычек. Каталог `data/` исключён из Git и **не должен загружаться в публичный репозиторий**.
- Браузер хранит собственную копию данных и очередь в IndexedDB. Эти данные не находятся внутри Git-проекта.
- Для резервного копирования сначала остановите сервер клавишами **Ctrl+C**, затем скопируйте `data/ritm.db` в защищённое место. Не публикуйте резервную копию на GitHub.

После изменения `HOST` или `PORT` сервер необходимо перезапустить. Настройки синхронизации хранят адрес сервера в данных соответствующего браузера; при переезде на другой ПК/адрес может потребоваться заново указать адрес на каждом устройстве.

## Публикация этого проекта на GitHub

Локальный Git-репозиторий уже подготовлен на ветке `main`. **Коммит и удалённый GitHub-репозиторий ещё не созданы.** Перед публикацией решите, будет репозиторий публичным или приватным. Даже приватный репозиторий — не место для базы данных, личных токенов или приватных ключей.

### 1. Создайте пустой репозиторий на GitHub

На GitHub выберите создание нового репозитория, например `ritm-tracker`. Не добавляйте там начальные README, `.gitignore` или лицензию: эти файлы уже находятся в локальном проекте. Для приватного проекта выберите **Private**, иначе **Public**.

### 2. Проверьте, какие файлы Git собирается включить

В PowerShell из каталога проекта выполните:

```powershell
git status --short --branch
git ls-files --others --exclude-standard
git check-ignore -v data/ritm.db data/habit-os.db node_modules certs .env .npmrc "трекер привычек.md"
```

В список публикации должны входить исходники в `server/` и `public/`, `package.json`, `package-lock.json`, документация, `.gitignore` и лицензии. **Не добавляйте** `data/`, `node_modules/`, каталог сертификатов, `.env`, `трекер привычек.md` или личные резервные копии. Корневой `.gitignore` исключает эти файлы. Если `git status` показывает базу или ключ, остановитесь и сначала исправьте правила исключения.

### 3. Добавьте только разрешённые файлы и просмотрите индекс

Для первой публикации добавьте явный список путей (не используйте `git add -f`):

```powershell
git add .gitignore LICENSE README.md SPEC.md package.json package-lock.json public server
git diff --cached --name-only
git diff --cached --stat
```

Убедитесь, что в staged-списке нет баз данных, зависимостей, секретов, сертификатов и локального исходного брифа. На этом этапе в репозитории ожидается около двух десятков файлов исходного кода и документации, а не тысячи установленных файлов. Если отображается существенно больше, **не коммитьте**: выполните `git status --short --ignored` и выясните, какая папка добавляется.

### 4. Создайте первый коммит

```powershell
git commit -m "Prepare standalone Ritm tracker"
git status --short --branch
```

Если Git сообщает, что не настроены имя и email автора, укажите свои данные локально для этого репозитория:

```powershell
git config user.name "Ваше имя"
git config user.email "ваш-адрес@example.com"
```

Не указывайте здесь пароль или токен GitHub.

### 5. Подключите GitHub и отправьте коммит

Замените `<ваш-логин>` своим логином GitHub:

```powershell
git remote add origin https://github.com/<ваш-логин>/ritm-tracker.git
git remote -v
git push -u origin main
```

При запросе доступа используйте авторизацию GitHub, которую предлагает Git Credential Manager или браузер; не записывайте токен в README, URL, исходники или `.npmrc`. После push откройте репозиторий на GitHub и проверьте список файлов, README, лицензию и отсутствие пользовательских данных. Если remote уже существует, не добавляйте второй раз: сначала проверьте его командой `git remote -v`.

## Удаление копии проекта с компьютера

**Не удаляйте папку проекта сразу после команды `git push`.** Сначала убедитесь на GitHub, что коммит и нужные файлы видны в правильном репозитории, затем сохраните `data/ritm.db` вне каталога проекта, если хотите сохранить историю. Остановите сервер (**Ctrl+C**) и скопируйте базу в личное место:

```powershell
New-Item -ItemType Directory -Force "$HOME\Documents\Ritm-Backup"
Copy-Item ".\data\ritm.db" "$HOME\Documents\Ritm-Backup\ritm.db"
```

Проверьте, что копия существует и имеет ненулевой размер. Убедитесь, что браузеры синхронизировали оставшиеся отметки. Только после проверки GitHub и резервной копии можно удалить каталог проекта обычным способом через Проводник Windows. Не выполняйте удаление, пока сервер ещё работает или пока не проверена резервная копия.
