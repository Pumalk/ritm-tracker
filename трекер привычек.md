# SPEC.md — HabitOS: персональный трекер привычек

> Рабочее название: HabitOS (меняется в manifest.webmanifest и шапке UI).
> Статус: спецификация зафиксирована. Реализация ведётся по шагам (раздел 14).
> Формат работы: пользователь пишет код сам; ассистент даёт архитектуру, ревью и правки.

## 0. Как работать с этим документом

- Для ИИ-ассистента: реализовывать строго по этой спецификации. Не расширять скоуп (раздел 2). Если требование противоречиво или отсутствует — не додумывать, задать вопрос пользователю.

## 1. Суть продукта

Бесплатный персональный трекер привычек в стиле «жизнь как игра»: геймифицированный дашборд, визуально копирующий референс (TikTok-пример: тёмный дашборд, сетка «привычка × день» с чекбоксами, эмодзи, проценты, стрики, графики, ТОП привычек). Референс — «Excel, превращённый в игру», внешний вид копируется 1-в-1 по стилистике (тёмная тема, те же типы блоков).

Использование: на телефоне (iPhone, в течение дня) и на ПК (Windows). Данные синхронизируются.

## 2. Скоуп: делаем / НЕ делаем

Делаем (v1):
- Привычки: эмодзи, название, цвет, теги/группы, опциональная числовая цель (3 л, 10к шагов) + опциональная запись фактического значения.
- Ежедневная отметка: чекбокс «выполнено/нет» (все привычки — ежедневные; других частот нет).
- Редактирование задним числом (выбор дня/недели, простановка галочек).
- Статистика: % по дням/неделям/месяцу, линейный график динамики, донат общего %, % по каждой привычке, стрики 🔥 (текущий и лучший ⚡), ТОП привычек, рейтинг по числу повторений, сравнение «прогресс/регресс» недели к неделе.
- PWA на iPhone (иконка на домашнем экране), браузер + установка как приложение на Windows.
- Синхронизация по домашнему Wi-Fi (ПК = сервер), офлайн-отметки на телефоне с отложенной синхронизацией.
- Тёмная тема (единственная).

НЕ делаем:
- Аккаунты, облачный сервер, платные сервисы, пуш-уведомления, текстовые заметки, Android, App Store, социальные функции, Syncthing, светлая тема.
- Привычки с частотой «не каждый день» (все — ежедневные).

## 3. Платформы и схема работы

- ПК (Windows): Node.js-сервер + SQLite + раздача фронтенда по HTTPS. Единственный источник истины.
- iPhone: PWA в Safari (добавляется на домашний экран). Хранит локальную копию + очередь изменений в IndexedDB; работает офлайн.
- Синхронизация: только в одной Wi-Fi-сети с ПК. Вне дома отметки копятся локально, при появлении доступа к серверу — автоматически отправляются.
- ПК как «десктоп-версия»: браузер + «Установить приложение» (Edge/Chrome) → иконка в меню «Пуск», отдельное окно. Electron/Tauri не используются.

## 4. Стек

| Слой | Технология | Почему |
|---|---|---|
| Backend | Node.js (>=18) + Express | пользователь знает JS |
| БД | SQLite через better-sqlite3 | файл, без установки СУБД, надёжно для личного проекта |
| Frontend | Vanilla JS (ES-модули) + HTML/CSS, без сборщика | пользователь знает сам; проще отлаживать |
| Графики | Chart.js (UMD-файл лежит локально в `public/vendor/`) | все нужные типы диаграмм; без CDN (офлайн!) |
| PWA | manifest + service worker (ручной, без workbox) | офлайн-кэш оболочки |
| HTTPS | mkcert (самоподписанный корневой CA) | нужен для SW и офлайн на iPhone |

Python для трекера не требуется. Все ассеты — локальные, никаких CDN.

## 5. Архитектура
┌─────────────┐   HTTPS (Wi-Fi)   ┌──────────────────────────┐
│ iPhone PWA  │ ◄────────────────►│ Node.js server (ПК)      │
│ IndexedDB   │   /api/sync       │  Express + better-sqlite3│
│ + очередь   │                   │  static: public/         │
└─────────────┘                   └──────────────────────────┘
        │                                      │
        └── офлайн: пишем локально, очередь ───┘

- Сервер слушает 0.0.0.0:8443 (HTTPS).
- Клиент держит last_rev — номер последней применённой ревизии изменений.
- Конфликты: last-write-wins по updated_at (ISO-строка). Для личного использования допустимо.
- Entries апсертятся по паре (habit_id, date), habits/tags — по id.

### 5.1 Офлайн и достижимость
- Индикатор в шапке: 🟢 синхронизировано / 🟡 в очереди N / 🔴 офлайн.
- Триггеры синхронизации: событие online, таймер каждые 30 с, после каждой локальной правки (debounce 2 с), кнопка «Синхронизировать».
- Проверка достижимости: GET /api/health с таймаутом 3 с.

### 5.2 HTTPS / сертификат
- mkcert генерирует корневой CA и сертификат сервера для localhost, 127.0.0.1 и LAN-IP ПК.
- Корневой CA устанавливается: на Windows (автоматически `mkcert -install`), на iPhone — вручную (раздел 13).
- После доверия CA на iPhone: SW регистрируется, приложение работает офлайн.

## 6. Модель данных (SQLite)
CREATE TABLE meta (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);

CREATE TABLE habits (
  id           TEXT PRIMARY KEY,              -- uuid
  title        TEXT NOT NULL,
  emoji        TEXT NOT NULL DEFAULT '',
  color        TEXT NOT NULL DEFAULT '#22d3ee',
  target_value REAL,                          -- NULL = нет числовой цели
  target_unit  TEXT,                          -- 'л', 'шагов', 'ч'…
  sort_order   INTEGER NOT NULL DEFAULT 0,
  archived     INTEGER NOT NULL DEFAULT 0,
  created_at   TEXT NOT NULL,                 -- ISO
  updated_at   TEXT NOT NULL
);

CREATE TABLE tags (
  id   TEXT PRIMARY KEY,
  name TEXT NOT NULL UNIQUE
);

CREATE TABLE habit_tags (
  habit_id TEXT NOT NULL REFERENCES habits(id) ON DELETE CASCADE,
  tag_id   TEXT NOT NULL REFERENCES tags(id)   ON DELETE CASCADE,
  PRIMARY KEY (habit_id, tag_id)
);

CREATE TABLE entries (
  id         TEXT PRIMARY KEY,                -- uuid
  habit_id   TEXT NOT NULL REFERENCES habits(id) ON DELETE CASCADE,
  date       TEXT NOT NULL,                   -- YYYY-MM-DD
  done       INTEGER NOT NULL DEFAULT 0,
  value      REAL,                            -- фактическое значение (опционально)
  updated_at TEXT NOT NULL,
  UNIQUE (habit_id, date)
);

CREATE TABLE changes (
  rev        INTEGER PRIMARY KEY AUTOINCREMENT,
  entity     TEXT NOT NULL,                   -- 'habit' | 'entry' | 'tag' | 'habit_tag'
  row_id     TEXT NOT NULL,
  op         TEXT NOT NULL DEFAULT 'upsert',  -- 'upsert' | 'delete'
  updated_at TEXT NOT NULL
);

Режим journal: PRAGMA journal_mode = WAL;.

## 7. API

| Метод | Путь | Тело / ответ |
|---|---|---|
| GET | /api/health | { ok: true, rev } |
| GET | /api/bootstrap | { habits: [], tags: [], entries: [], rev } — полная выгрузка при первом подключении |
| POST | /api/sync | req: { since_rev, changes: [ { entity, id, data, op, updated_at } ] } → res: { changes: [ { entity, id, data, op, updated_at } ], rev } |

Правила сервера в /api/sync:
1. Каждый входящий change применяется как upsert/delete с LWW: применять, только если incoming.updated_at > stored.updated_at.
2. entries матчить по (habit_id, date); при конфликте двух разных id — слить в существующую строку (LWW), в changes писать фактический row_id.
3. Каждый применённый change добавляется в changes; ответ содержит все строки с rev > since_rev (полные данные, сервер дочитывает из таблиц; для op=delete → `data: null`).
4. Тело запроса ≤ 1 МБ.

Статика: express.static('public') по тому же HTTPS.

## 8. Клиентское хранилище и синхронизация

IndexedDB, базы/сторы: meta (`last_rev`, server_url`), `habits, tags, habit_tags, entries, queue.
- Любая правка UI → немедленно в локальный стор + в queue + перерисовка.
- Sync-цикл: собрать queue → POST /api/sync { since_rev, changes } → применить серверные changes (тот же LWW) → last_rev = rev → очистить отправленную очередь.
- Первый запуск на телефоне: экран «Адрес сервера» → ввод https://192.168.X.Y:8443 → GET /api/bootstrap → сохранить, last_rev = rev.

## 9. Метрики и формулы

- Первый день недели — понедельник. Даты — YYYY-MM-DD, в UI — DD.MM.
- active(habits, day) = неархивированные, created_at <= day.
- % дня = done / active.
- % недели = Σdone / Σactive по дням недели (до сегодня включительно).
- % привычки за период = дни с done / (дни периода ∩ [created_at..today]).
- streak текущий: идём назад от сегодня; если сегодня не отмечено — от вчера (стрик не «сгорает» до конца дня).
- streak лучший (⚡): максимум в истории.
- прогресс/регресс: Δ = % текущей недели − % прошлой недели; показать стрелку ↑ (зелёная) / ↓ (красная) и значение Δ.
- ТОП привычек: сортировка по % за выбранный период, топ-7.
- рейтинг по повторениям: сортировка по Σdone за период.

### 10.2 Навигация
Нижний таб-бар (на телефоне) / верхние вкладки (на широком экране): Сетка, Статистика, Привычки.

### 10.3 Экран «Сетка» (главный)
- Шапка: название, индикатор синхронизации, переключатель недель ‹  15–21.06  ›.
- Таблица: строки — привычки (эмодзи + название), столбцы — дни недели.
- Шапка столбцов: номер дня + имя дня (Пн..Вс); ячейка даты подкрашена по % дня: ≥80 --ok, 40–79 --warn, <40 --bad.
- Чекбокс: пустой — белый квадрат-контур; выполнено — заливка --ok + белая галочка; текущий/выбранный день — синяя обводка ячейки (как в референсе).
- Тап по чекбоксу = toggle. Если у привычки есть числовая цель — после toggle «выполнено» раскрывается поле ввода значения (опционально).
- Редактирование задним числом = переключение на прошлую неделю + тапы. Будущие дни заблокированы.

### 10.4 Экран «Статистика»
Селектор периода: неделя / месяц / всё время. Блоки сверху вниз:
1. KPI-строка: донат общего % (зелёный/серый, % в центре) + блок «Неделя к неделе»: текущий %, Δ со стрелкой и цветом (прогресс/регресс).
2. По неделям: вертикальные бары % за последние 8 недель (cyan), значение над баром.
3. По месяцам / динамика: линейный график (area) дневного % за 30 дней (cyan).
4. По каждой привычке: список строк: %  [горизонтальный бар purple]  🔥 текущий  ⚡ лучший.
5. ТОП внедрённых привычек: горизонтальные бары magenta, топ-7, с эмодзи и названиями.
6. Рейтинг по числу повторений: таблица эмодзи название | Σdone | %.

### 10.5 Экран «Привычки»
- Список привычек (сортировка стрелками ▲▼), свайп/кнопка «Архив».
- Форма создания/редактирования: название, эмодзи, цвет (палитра-свотчи), теги (чипы: создать/привязать), числовая цель (значение + единица, опционально).
- Раздел «Архив» с восстановлением.

### 10.6 Прочее
- Все данные рисуются из локального стора мгновенно (offline-first).
- Анимации минимальные: появление галочки, плавное обновление баров.

## 11. PWA-требования

- manifest.webmanifest: name, display: standalone, background_color/theme_color из токенов, иконки 192/512 (PNG, maskable).
- Meta для iOS: apple-mobile-web-app-capable, apple-mobile-web-app-status-bar-style: black-translucent, safe-area отступы в таб-баре (`env(safe-area-inset-bottom)`).
- Service worker: cache-first для оболочки и ассетов (включая vendor/chart.js`), network-first с офлайн-фолбэком для `/; API не кэшировать.
- Обновление кэша оболочки: версионирование префикса кэша (`cache-v<N>`), activate → чистка старых.

## 13. Установка и запуск (Windows + iPhone)

Проверка окружения (вывод — ассистенту на ревью):node -v        # нужно >= 18
npm -v
git --version
code --version

Каркас и зависимости:mkdir habit-os && cd habit-os
git init
npm init -y
npm i express better-sqlite3

HTTPS (mkcert):winget install --id FiloSottile.mkcert -e
mkcert -install
mkdir certs && cd certs
mkcert localhost 127.0.0.1 192.168.0.100   ← заменить на реальный LAN-IP ПК
mkcert -CAROOT                             ← путь к rootCA.pem

Файрвол (разрешить порт):netsh advfirewall firewall add rule name="HabitOS" dir=in action=allow protocol=TCP localport=8443

iPhone (одноразово):
1. Передать rootCA.pem на телефон (мессенджер/почта/облако).
2. Открыть файл → «Профиль загружен» → Настройки → Основные → VPN и управление устройством → установить профиль.
3. Настройки → Основные → Об этом устройстве → Настройки доверия сертификатов → включить полное доверие корню.
4. Safari → открыть https://<IP-ПК>:8443 → «Поделиться» → «На экран “Домой”».

Рекомендации:
- Закрепить за ПК статический IP (резервирование в роутере), чтобы адрес не менялся.
- Сервер запускать при старте Windows (автозагрузка: ярлык в shell:startup с `node server/index.js`).

## 14. Порядок реализации (шаги → ревью после каждого)

1. Каркас: сервер поднимается по HTTPS, отдаёт заглушку; сертификаты, автозагрузка, файрвол.
2. БД: схема (раздел 6), db.js; сид из 3 тестовых привычек.
3. API: /api/health, /api/bootstrap, /api/sync; проверка через curl/Postman (push/pull, LWW).
4. Фронтенд-каркас: index.html, токены темы, таб-бар, роутинг экранов.
5. Экран «Сетка» на локальных моках: рендер недель, чекбоксы, подсветка дат.
6. IndexedDB-сторы + очередь + привязка UI к стору (пока без сервера).
7. Клиентский sync + экран первого подключения (адрес сервера) + индикаторы.
8. Экран «Статистика»: metrics.js + все 6 блоков на Chart.js.
9. Экран «Привычки»: CRUD, теги, архив, сортировка.
10. PWA: manifest, sw.js, иконки; установка на iPhone; офлайн-проверка.
11. Числовые цели: ввод значения, отображение в сетке/статистике.
12. Полировка: цвета/анимации под референс, пустые состояния, edge-cases.
13. Прогон приёмки (раздел 15), исправления.

## 15. Приёмочные критерии

- [ ] iPhone: иконка на домашнем экране, открывается, работает офлайн (самолётный режим).
- [ ] Отметки в офлайне сохраняются и синхронизируются при возврате в Wi-Fi без потерь и дублей.
- [ ] Редактирование задним числом меняет все графики корректно.
- [ ] Все 6 блоков статистики считаются по формулам раздела 9 (сверить вручную на тестовом наборе).
- [ ] Стрики: текущий/лучший считаются на ручных примерах (пропуски, серия с сегодня/вчера).
- [ ] Конфликт: отметить одну привычку на двух устройствах по-разному в офлайне → после синхронизации обе показывают одинаковое (последнее по времени) значение.
- [ ] ПК: «Установить приложение» в Edge/Chrome даёт иконку и отдельное окно.
- [ ] Никаких внешних CDN/шрифтов/сервисов; репозиторий не содержит certs/ и data/.

## 17. Зафиксированные решения и заметки

- Имя по умолчанию HabitOS; смена — в manifest + шапке.
- Неделя начинается с понедельника.
- Архивированная привычка скрывается из сетки и текущих KPI; история сохраняется и возвращается при разархивировании.

- Порт 8443; при занятости — поменять в server/index.js и в инструкциях.
